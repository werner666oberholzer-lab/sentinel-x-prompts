# Contributing

1. Identify the affected prompt or template.
2. Explain the objective.
3. Describe security implications.
4. Describe privacy implications.
5. Describe Responsible AI implications.
6. Preserve the authority model.
7. Preserve deny-by-default behavior.
8. Add or update validation checks.
9. Update the changelog.
10. Obtain review for security-sensitive changes.

Explicit security review is required for changes that weaken Security Governor authority, capability restrictions, human approvals, tenant isolation, data classification, audit integrity, emergency controls, secrets protection, tool-output validation, or model-provider restrictions.

Keep examples fictional and secret-free. Run both validation scripts where practical. Do not describe prompt text as a security control or claim generated software is secure without evidence.
